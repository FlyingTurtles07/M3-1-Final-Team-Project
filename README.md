# 온가족 한상 – 웹페이지 6페이지 상세 정리안

검토·수정용 초안 (모바일 반응형 포함) · 💬 `[검토]` 표시는 팀에서 결정이 필요한 항목입니다.

## 0. 서비스 한 줄 정의

냉장고 속 식재료와 오늘 구매한 식재료를 바탕으로, **가족 모두가 함께 먹을 수 있는 하나의 요리**를 제안하는 AI 식단 Agent 서비스. 알레르기가 있는 가족, 유동식이 필요한 환자 등 구성원별 조건을 반영해 공통 요리를 만들고, 조리 마지막 단계에서 양념·곁들임·식감·분량을 조절한다. 핵심 경쟁력은 가족 수만큼 따로 요리하지 않아도 되는 **한 번의 조리**다.

### 핵심 원칙 (모든 페이지 공통)

- **공통 요리 + 맞춤 변형**: 기본 레시피를 먼저 설계하고, 마지막 단계에서 양념·곁들임·분량을 조절한다.
- **알레르기 재료는 처음부터 제외**: 나중에 빼는 방식이 아니라 교차오염까지 고려한다. 유동식 등 특별한 식사 형태도 안전을 우선한다.
- **사진은 저장하지 않음**: 냉장고·영수증 사진은 재료 인식·확인에만 쓰고, 확인된 식재료명만 저장한다(수량 제외).
- **사용자 확인 후 확정**: 인식된 재료는 사용자가 확인·수정한 뒤에만 데이터로 등록한다.
- **가공식품·각종 양념은 기본 식재료 재고에서 제외**한다.
- **안전 재검사**: 생성된 레시피가 금지 재료·식사 조건을 위반하지 않는지 규칙 코드로 다시 검증한다. 검증은 백엔드에서 식약처 등 공공 오픈 API로 수행하고, 사용자 화면에는 검증 완료 확인과 고지만 표시한다.
- **참고용 안내**: 태그는 안전을 보증하지 않는다. 공개 게시물에는 “참고용이며 성분표를 꼭 확인하세요”, “AI가 생성한 레시피입니다”를 표시한다.

* **분량 기준 통일**: 레시피는 4인분(성인 1인분×4) 기준으로 제공한다. 단위는 g·mL(1컵 200mL, 1큰술 15mL)이며 재료는 손질 후 먹는 부분 기준이다. 분량은 AI가 임의로 정하지 않고 재료 사전의 표준 기준량 규칙으로 산출한다.
* **안전 검사 판정**: 알레르기·당뇨식·저염식은 식약처 식품영양성분DB(수치)와 PubMed(근거 논문)를 사용해 검증하고 결과를 통과·보류·제외로 처리한다. 근거나 데이터가 부족하거나 수치 기준이 전문가 검수 전이면 통과로 단정하지 않고 보류한다. 유동식·이유식은 자동 검증 범위 밖이라 전문가 기준 확인 전까지 보류한다.

### 페이지 흐름

메인(로그인/회원가입) → ② 가족 프로필 → ③ 식재료 등록 → ④ 레시피 3개 추천 → ⑤ 레시피 보관함 → ⑥ 공유·감사

- 모바일: 하단 탭 6개 / PC: 상단 메뉴
- 각 단계의 결과가 다음 단계의 입력이 된다(프로필 → 재료 → 레시피 → 피드백 → 다음 추천).

## 1. 메인 화면 (로그인 · 회원가입)

### 목적

서비스 가치를 한눈에 전달하고, 로그인·회원가입으로 진입시킨다.

### 화면 구성

1. **히어로 영역**: 서비스명, 슬로건(예: “한 번의 조리로, 온 가족의 한 상”), 보조 설명(알레르기·식감·건강 조건이 달라도 하나의 요리로)
2. **핵심 기능 카드 ****2****개**
   - 가족 공통 요리 + 맞춤 변형
   - 사진·영수증 기반 식재료 인식 (원본 미저장)
3. **로그인/회원가입 카드** (탭 전환)
4. **둘러보기** 버튼(가입 없이 흐름 확인용)

### 입력 항목

| 구분 | 항목 | 비고 |
| --- | --- | --- |
| 로그인 | 이메일, 비밀번호 | 비밀번호 찾기 링크 |
| 회원가입 | 이메일, 비밀번호, 비밀번호 확인 |  |
| 회원가입 | (필수) 개인정보 수집·이용 동의 | 약관 보기 링크 |

### 동작·상태

- 탭 전환 시 입력 폼이 로그인 ↔ 회원가입으로 바뀐다.
- 가입 완료 → 가족 프로필 화면으로 이동한다.
- 입력 오류(형식, 비밀번호 불일치, 동의 누락)는 항목 아래에 안내 문구로 표시한다.
- 안내: “건강 정보는 가족 프로필 입력 단계에서 별도 동의를 받고 암호화해 보관합니다.”

## 2. 가족 구성원 프로필 입력 화면

### 목적

구성원별 알레르기, 건강상 식사 조건(당뇨식, 저염식, 일반식, 유동식, 이유식), 기타 참고사항(식단 목표, 기피 음식 등)-사용자가 자유롭게 기재을 등록해 모든 추천의 기준 데이터를 만든다.

### 화면 구성

1. **구성원 목록(가로 스크롤 칩)**: 이름 · 구분 · 알레르기 경고(⚠) 표시, “+ 새 구성원”
2. **프로필 입력 폼** (구성원 1명씩): 선택지 중에 해당 사항이 없을 경우, 직접 입력 할 수 있는 빈칸을 만들고 칸 안에 '직접 입력'이라고 표기&#32;
3. **저장** 버튼, **다음: 식재료** 버튼

### 입력 항목

| 항목 | 입력 방식 | 예시 선택지 |
| --- | --- | --- |
| 이름(별칭) | 텍스트 | 아빠, 엄마, 민준 |
| 연령대 | 선택 | 성인, 어린이, 노인, 환자(회복식) |
| 알레르기 | 다중 선택 칩(빨간색 강조, 복수선택 가능) | 땅콩, 견과류, 우유, 달걀, 밀, 대두, 갑각류, 생선, 없음, 직접 입력 |
| 건강상 식사 조건 | 다중 선택 칩(복수선택 가능) | 당뇨식, 저염식, 일반식, 유동식, 이유식 (유동식·이유식은 전문가 확인 후 제공) |
| 기타 참고사항 | 텍스트(쉼표 구분) | 식단 목표, 기피 음식 |
| 건강 정보 수집·이용 동의 | 체크박스(필수) | 대리 입력 시 해당 가족의 동의를 확인했음을 함께 체크 |

### 동작·상태

- 구성원 이름 왼쪽 옆에 캐릭터를 선택한 후 화면에 표시한다.
- 저장 시 구성원 목록에 카드가 추가된다. 동의 미체크 시 저장할 수 없다.
- 알레르기가 있는 구성원은 목록에서 ⚠ 표시와 빨간색으로 구분한다.
- 구성원은 추가·수정·삭제할 수 있고, 삭제 시 관련 건강 정보도 함께 삭제됨을 안내한다.
- 이후 피드백에서 기피 후보가 제안되면, **사용자가 승인한 경우에만** 이 프로필에 반영한다.
- 프로필에서 선택 또는 작성한 내용은 개인정보 관련 사용동의, 유출되지 않는다 등의 내용의 안내 문구를 포함시킨다.

## 3. 식재료 등록 화면 (사진·영수증·직접 입력)

### 목적

냉장고 사진, 영수증 사진, 직접 입력으로 식재료 데이터를 만들고, 사용자가 확인·수정한 재료만 확정한다.

### 화면 구성

1. **입력 방식 탭**: 🧊 냉장고 사진 / 🧾 영수증 사진 (+ 직접 입력)
2. **업로드 영역**: 촬영하기 또는 앨범에서 선택 (모바일도 동일)
3. **개인정보 안내**: “사진 원본은 저장하지 않고, 확인한 식재료명만 저장합니다. 영수증은 신선식품만 추출하고 구매 장소·가격·카드번호는 저장하지 않습니다. 가공식품·양념은 재고에서 제외됩니다.”
4. **인식 결과 목록**: 재료명 · 삭제(✕) (의심 재료는 ‘맞아요/아니에요’로 확인)
5. **재료 추가 입력줄**: 재료명 + 추가
6. **확정 버튼**: “확인한 재료로 레시피 추천받기”

### 동작·상태

| 상황 | 화면 동작 |
| --- | --- |
| 인식 성공 | 재료 목록 표시, 건수 안내 |
| 오인식 | 재료명 칸을 직접 수정 |
| 누락 | 하단 입력줄로 재료 추가 |
| 불필요 항목 | ✕로 삭제 |
| 금지 재료(알레르기 등) 확인·의심 | 해당 항목을 **빨간색**으로 표시 + 경고 문구(“레시피에서 제외됩니다”) |
| 가공식품·양념 | 자동으로 재고 집계에서 제외 |
| 인식 실패/저화질 | 재촬영 안내, 직접 입력으로 전환 유도 |

- 사용자가 확인·수정한 **식재료명만 확정·저장**하고, 사진 원본은 저장하지 않는다.
- 식재료의 수량은 일단 신경쓰지 않는다.
- 영수증은 구매한 식재료(신선식품)만 추출하고 구매 장소, 가격, 카드번호 등 불필요한 정보는 저장하지 않는다.
- 금지 재료가 사진에서 '의심'일 때 표시 문구와 확인 절차를 거친다.

## 4. 레시피 3개 추천 화면

### 목적

가족 프로필, 확정된 식재료, 근거 문서를 바탕으로 가족이 함께 먹을 수 있는 공통 요리 3개와 구성원별 변형 방법을 제안한다.

### 화면 구성

상단: 안전 검사 완료 표시(검사 내용은 노출하지 않고 완료 여부만 표시) · “AI가 생성한 레시피입니다” 배지

레시피 카드 3개(PC는 3열, 모바일은 세로 배치). 카드별 구성:

1. 요리 이미지, 요리 이름, 소요 시간, 상세 레시피
2. **태그**: 사용 재료, 식사 조건, 식사 목표, 기피 재료 참고 후 반영(예: 견과류 제외, 부드러운 식감 참고)
3. **공통 베이스 레시피**: 한 번에 조리하는 기본 방법
4. **구성원별 변형**: 이름별 양념·곁들임·식감·분량 조절과 변형 이유
5. **“이 레시피 선택”** 버튼

### 분량 기준 (4인분)

- **단위**: g·mL 기본(개수는 g 병기), 1컵 200mL · 1큰술 15mL · 1작은술 5mL
- **기준**: 손질 후 먹는 부분(가식부) 기준으로 표시하고, 구입량은 폐기율로 환산
- **반올림(팀 결정안)**: g 5단위, mL 10단위, 개수·큰술 0.5단위
- **분량 산출**: 식품군별 1교환단위량 × 끼니 배분 교환단위 수로 재료 사전의 기준량을 정하고, AI는 분량을 정하지 않는다.
- `[검토]` 식품교환표 수치의 이용 가능 여부, 어린이·노인 분량 환산계수(영양섭취기준 근거)

하단 안내: “참고용이며 성분표를 꼭 확인하세요.”

### 동작·상태

- 알레르기 재검사에서 금지 재료가 확인되면 해당 레시피를 제외하고 다시 생성한다.
- 정보가 불충분하면 안전 판정을 보류하고 사용자에게 확인을 요청한다. 안전 재검사는 백엔드에서 식약처 등 공공 오픈 API로 검증하며, 화면에는 ‘안전 검사 완료’ 확인과 “식약처 등 공공 데이터 기준, 참고용이며 성분표를 꼭 확인하세요” 고지만 노출한다. 판정은 통과(‘안전 검사 완료’) / 보류(‘확인이 필요해요’) / 제외(해당 레시피를 빼고 다시 생성) 3가지이며, 유동식·이유식 구성원이 있거나 의심 재료를 확인하지 않았거나 수치 기준이 전문가 검수 전이면 보류로 표시한다.
- 알레르기 재료는 변형 단계에서 빼는 것이 아니라 **처음부터 제외**한다. 1차 요리 후 따로 알레르기 재료에 반응하지 않는 다른 가족 구성원들을 위해 추가하는 방향으로 진행한다.
- 선택하면 이 레시피 저장하기 화면 또는 공유·감사표시하기 화면으로 이동한다.
- 추천 이유(어떤 재료·프로필 조건을 반영했는지)를 카드에 짧게 표시한다.
- 조리 순서는 정해진 형식(재료 → 공통 조리 → 변형 → 주의사항)으로 제공한다.
- 재추천(“다른 메뉴 보기”) 버튼을 포함시키고, 추천 레시피 3가지가 마음에 안드는 경우 새로운 레시피 3가지를 추천한다.

## 5. 레시피 보관함 화면

### 목적

마음에 드는 레시피를 저장해 기록으로 남기고, 검색해서 다시 요리할 때 재사용한다. 레시피 추천(4번)과 공유·감사(6번) 사이에 둔다.

### 화면 구성

1. **검색창**: 레시피 이름·재료로 검색
2. **필터**: 전체 / 즐겨찾기
3. **저장 레시피 카드**: 요리 이미지, 이름, 저장일, 소요 시간, 태그, 메모, 즐겨찾기(⭐), 삭제
4. **다시 요리하기**: 상세 레시피, 재료 분량(4인분), 구성원별 변형, 현재 등록된 식재료와 비교한 보유·부족 재료, 안전 검사 완료 표시
5. **“이 레시피로 요리 후 공유·감사” 버튼**: 공유·감사 화면으로 이동

### 저장 항목

| 항목 | 내용 |
| --- | --- |
| 레시피 | 이름, 이미지, 소요 시간, 태그, 상세 레시피, 구성원별 변형 |

## 9. 안전 검사 설계 (백엔드)

레시피 후보가 만들어지면 사용자에게 보여주기 전에 서버가 알레르기·당뇨식·저염식을 검사한다. 근거로 쓰는 공개 정보는 **PubMed(논문 근거)** 와 **식약처 식품영양성분DB(재료별 수치, 공공데이터포털 Open API)** 두 곳이다. 사용자 화면에는 세부 사유를 보이지 않고 **통과(‘안전 검사 완료’) / 보류(‘확인이 필요해요’) / 제외(해당 레시피를 빼고 다시 생성)** 결과와 고지 문구만 표시한다. 판정 우선순위는 제외 > 보류 > 통과다.

### 검사별 사용 정보와 방법

| 검사 | 사용하는 정보 | 검사 방법 | 판정 |
| --- | --- | --- | --- |
| 알레르기 | 구성원 알레르기(프로필), 재료 사전(재료명 → 포함 알레르기 성분, 복합 재료 여부) | 규칙 대조. 재료 사전은 식약처 알레르기 표시 대상 고시와 대조해 팀이 관리한다. 1차 조리 후 추가 재료는 알레르기 없는 구성원 몫에만 허용한다. | 해당 성분 포함 → 제외 / 사전에 없는 재료·알레르기, 성분이 제품마다 다른 복합 재료 → 보류 |
| 당뇨식 | 식약처 DB의 100g당 당류·탄수화물, PubMed 근거 태그(재료군별 유리/불리) | 재료별 수치를 기준값과 비교하고, 재료군 근거 태그를 설명·대체 제안용으로 붙인다. 근거 태그는 판정을 통과로 바꾸지 못한다. | 기준 초과 → 보류 또는 제외 / 데이터 없음 → 보류 |
| 저염식 | 식약처 DB의 100g당 나트륨, 레시피 재료 분량(g) | 재료별 나트륨 비교 + 레시피 전체 나트륨 합산 후 4로 나눈 1인분 값을 한도와 비교한다. | 초과 → 보류 또는 제외 / 분량·데이터 없음 → 보류 |
| 유동식·이유식 | 프로필의 식사 조건 | 질감·월령 기준은 자동 검증 범위 밖 | 전문가 기준 확인 전까지 보류 |

### PubMed 사용 방식 (근거)

- **검색식**: 당뇨 식재료 선택, 저염식(고혈압·나트륨), 알레르기 교차반응 3개를 준비한다. 서버 정기 작업이 E-utilities로 관련도순 상위 10편을 가져온다.
- **근거 태그 확정은 사람이 한다**: 새 논문은 ‘검토 대기’ 목록에만 올리고, 초록을 자동 해석해 태그를 만들지 않는다. 확정된 태그만 판정 설명에 쓴다.
- **재료군별 방향(현재 당뇨 기준)**: 콩류·통곡물·식이섬유 풍부 채소는 유리, 정제곡물·첨가당·붉은 고기·가공육은 불리, 견과류는 혈당에는 유리하나 견과류 알레르기 구성원에게는 알레르기 규칙이 우선한다. 두부·대두는 콩류 메타분석에 포함되지 않아 근거 미수집이다.
- **사용자 요청 중에는 PubMed를 호출하지 않는다.** 미리 확정된 근거 태그만 사용한다.
- **당뇨 근거 논문 후보 10편**: 영양 요법 합의 보고서(Diabetes Care 2019, PMC7011201), 저GI 식단 메타분석(PMID 12882846), 2형 당뇨 식이 GI 혈당 메타분석(PMID 29562676), 저GI 식단 대사질환 메타분석(PMC8778967), 두류 혈당 메타분석(Diabetologia 2009), 두류 최신 메타분석(Eur J Nutr, PMC8854292), 견과류 혈당 조절(PMID 25076495), 통곡물 용량-반응 메타분석(2024), 식이섬유 메타분석(J Am Board Fam Med), 식물성 식단·붉은 고기 리뷰(PMC13516182). 일부는 식별번호를 아직 확인하지 못했다.

### 식약처 식품영양성분DB 사용 방식 (수치)

- 재료 사전의 식약처 검색명으로 조회하고, **이름이 정확히 일치하는 항목만** 쓴다. 모호하거나 없으면 보류한다.
- 100g당 당류·탄수화물·나트륨(·식이섬유)을 가져와 위 규칙에 적용하고, 호출 결과는 캐시한다(개발 계정은 일 트래픽 제한이 있다).
- 요청 변수와 응답 필드는 활용신청 후 받는 참고문서로 확정한다(현재 미검증).

### `[검토]` 확정이 필요한 항목

- 당뇨식·저염식의 수치 기준(임시값 사용 중): 대한당뇨병학회 등 가이드라인에 근거해 전문가가 확정, 확정 전에는 통과를 내지 않고 보류
- 알레르기 재료 사전의 식약처 고시 대조와 재료·별칭 확장
- 저염식·알레르기 교차반응 논문 수집, 두부·대두 근거
- 식약처 API 요청·응답 필드 확정
- 100g 기준 재료 선별은 거친 방법이므로, 1회 섭취량 기준의 보완 여부

## 10. 4인분 기준량의 근거 표준 4가지

모든 레시피는 **4인분(성인 1인분×4) 기준**으로만 제공한다. 분량은 AI가 정하지 않고, 재료 사전의 기준량을 규칙 엔진이 채운다. 아래 표준 4가지가 그 근거다.

| 표준 | 사용하는 정보 | 사용 방식 | 확인할 점 |
| --- | --- | --- | --- |
| ① 당뇨병 식품교환표(대한당뇨병학회·대한영양사협회·한국영양학회, 2023 제4판) | 식품군 6개(곡류·어육류·채소·지방·우유·과일)와 군별 1교환단위량 | 재료를 식품군에 분류하고, 1인분 기준량 = 1교환단위량 × 끼니 배분 교환단위 수로 정한다. 4인분은 ×4. | 수치의 이용·인용 가능 여부 |
| ② 식약처 식품영양성분DB(국가표준식품성분표 계열) | 100g당 영양소, 폐기율, 식품 중량(개당 g) | 가식부 기준으로 표시하고 구입량은 폐기율로 환산, 개수↔g 환산에 사용. 안전 검사 수치도 같은 데이터 사용 | API 필드 확정 |
| ③ 식약처 1회 섭취참고량(영양표시) | 만 3세 이상이 통상 섭취하는 식품별 1회 섭취량 | 가공식품·시판 양념 등 교환표에 없는 품목의 1인분 기준 | 해당 고시 표 확인 |
| ④ 식약처 조리식품 레시피 DB | 1인분 중량, 열량, 탄수화물, 나트륨, 재료정보 | 완성된 4인분 레시피의 총 중량·열량·나트륨을 비슷한 메뉴의 범위와 비교해 크게 벗어나면 보류·재생성 | 비교 범위 규칙은 팀 결정 |

### 적용 순서

1. 재료 사전에 식품군·1교환단위량·1인분 기준량·가식부 비율·개당 중량을 저장한다(표준 ①②③에서 자동 수집).
2. AI는 재료와 조리법만 제안하고, 규칙 엔진이 4인분 분량을 채운다.
3. 채운 분량으로 나트륨 합산 등 안전 검사(9항)를 수행한다.
4. 완성된 레시피를 표준 ④와 비교해 상식 범위를 확인한다.
5. 표시: g·mL 기본(1컵 200mL, 1큰술 15mL, 1작은술 5mL), 반올림은 g 5단위·mL 10단위·개수와 큰술 0.5단위(팀 결정안)

### `[검토]` 확정이 필요한 항목

- 식품교환표 수치 이용 가능 여부(불가하면 국가표준식품성분표와 영양섭취기준으로 직접 계산)
- 어린이·노인 분량 환산계수(총량은 4인분 고정, 구성원별 배분은 변형 단계에서 조절)
- 표준 ④와의 비교 범위, 계량 단위의 공식 출처 확인
