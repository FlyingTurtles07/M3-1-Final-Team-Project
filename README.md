# 온가족 한상

> 냉장고 재료로, 알레르기·식사 조건이 서로 다른 가족이 **한 번에 함께 먹을 수 있는 요리**를 제안하는 AI 레시피 서비스

코디세이 AI 네이티브 과정 캡스톤 파이널 프로젝트 · 7조

| 구분 | 주소 |
|---|---|
| 서비스 화면 | https://m3-1-final-team-project.onrender.com/ |
| API 서버 (문서: `/docs`) | https://onfamily-hansang-api.onrender.com |

> 무료 서버라 한동안 쉬다가 처음 열면 응답까지 50초쯤 걸릴 수 있습니다.

---

## 1. 왜 만들었나

가족 중에 알레르기가 있는 사람, 싱겁게 먹어야 하는 사람, 당을 조절해야 하는 사람이 함께 살면, 요리하는 사람은 메뉴를 여러 번 따로 만들거나 매번 재료를 일일이 확인해야 합니다.

**온가족 한상**은 주부의 입장에서 출발했습니다.

- 냉장고에 있는 재료와 오늘 사 온 재료만으로 (가공식품·양념 제외)
- 가족 구성원마다 다른 알레르기·식사 조건을 함께 고려해서
- **한 번 조리하고, 필요한 시점(분기점)에서만 덜어내 따로 맞추는** 레시피를 제안합니다.

## 2. 주요 기능

| 단계 | 화면 | 내용 |
|---|---|---|
| 1 | 회원가입·로그인 | 개인정보·건강 정보 처리 동의 |
| 2 | 가족 프로필 | 구성원별 캐릭터, 알레르기, 식사 조건(당뇨식·저염식·일반식 등) |
| 3 | 재료 확인 | 냉장고 사진·영수증 사진·직접 입력 → 재료 이름만 저장 (**사진은 저장하지 않음**), 가족이 피해야 할 재료는 빨간색 표시 |
| 4 | 오늘의 한상 | 재료로 만든 레시피 3개 + 구성원별 **분기점**(간 하기 전 덜어내기, 알레르기 재료는 나중에 추가 등) + 안전 검사 결과 |
| 5 | 식사 후 리뷰 | 가족별 "잘 먹었어요 / 남겼어요"와 의견 → 다음 추천에 반영, 마음에 들면 보관함에 저장 |
| 6 | 식사 사진 기록·공유 | 요리 사진과 레시피를 태그와 함께 공유, **가족 의견 링크**(카카오톡) · **QR 코드**(인스타그램) |
| 7 | 다른 집 한상 | 다른 가정이 공유한 요리 보기, 좋아요·신고 |
| 8 | 저장한 요리 · 나만의 레시피북 | 묶음별 보관, 가족이 링크로 남긴 의견 모아 보기 |

## 3. AI와 안전 설계

### 레시피 추천 정책 22종
가족 조건에 맞는 정책만 골라 AI 지시문에 함께 넣습니다. 정책 원문은 Firestore `recipe_policies`에 저장되어 있습니다.

| 분류 | 코드 | 내용 |
|---|---|---|
| 알레르기 (10) | AL-01 ~ AL-10 | 알류, 우유, 땅콩, 대두, 밀, 메밀, 새우·게, 고등어, 호두·잣, 조개류·오징어 (식품 등의 표시·광고에 관한 법률 시행규칙 별표 2 기준) |
| 당뇨식 (4) | DM-01 ~ DM-04 | 탄수화물·당류, 식이섬유와 곡물의 질, 첨가당·가당음료, 판정 우선순위 |
| 저염식 (4) | NA-01 ~ NA-04 | 재료별 나트륨, 1인분 합산 한도, 시판 양념·국물, 마지막 단계 양념 조절 |
| 정량 (1) | QT-01 | 4인분(성인 1인분 × 4) 기준 |
| 유동식 (3) | LQ-01 ~ LQ-03 | 맑은 유동식, 일반 유동식, 연하곤란식 — **준비 중(비활성)** |

- 정책 원문: [`docs/레시피_추천_정책_22종.md`](docs/레시피_추천_정책_22종.md)
- AI에는 가족의 이름·나이를 보내지 않고, 가족 전체의 알레르기·식사 조건만 보냅니다.

### 안전 검사 (규칙 엔진)
AI가 만든 레시피를 그대로 보여 주지 않고, 서버의 규칙 엔진이 다시 검사합니다.

| 판정 | 화면 문구 | 기준 |
|---|---|---|
| 통과 | 안전 검사 완료 | 확인된 정보에서 회피 대상이 없음 (**안전 보증이 아님**) |
| 확인 필요 | 확인이 필요해요 | 알레르기 재료 포함(분기점 안내), 저염식 1인분 나트륨 770mg 초과, 수치 확인 불가, 당뇨식(기준값 확정 전), 유동식·이유식 |

- 영양 수치: 식약처 식품영양성분 DB (공공데이터포털)
- 레시피·재료·공유 화면에 고지문 표시: *"식약처 등 공공 데이터 기준, 참고용이며 성분표를 꼭 확인하세요"*
- `[임시값]` 저염 한 끼 770mg, 당뇨식 기준값 등은 **전문가 확정 전** 값입니다.

## 5. 폴더 구조

```text
.
```

API 목록과 환경변수는 [`backend/README.md`](backend/README.md)에 있습니다.

## 6. 내 컴퓨터에서 실행

```bash
# 1) 서버
cd backend
python -m venv .venv
.venv\Scripts\activate          # macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
copy .env.example .env          # 필요한 키만 채우기 (macOS/Linux: cp)
uvicorn main:app --reload       # http://localhost:8000/docs

# 2) 화면 (새 터미널)
cd Final
python -m http.server 8765      # http://localhost:8765
```

화면을 `localhost`에서 열면 `api.js`가 자동으로 `http://localhost:8000` 서버에 연결합니다.

> `.env`, Firebase 서비스 계정 키(`*firebase-adminsdk*.json`)는 **절대 커밋하지 않습니다.** (`.gitignore`에 등록되어 있음)

### 협업 방식
```text
각자 브랜치에서 작업 → Commit → Push → Pull Request → 리뷰 → Merge → main
```
- `main`은 보호 브랜치로, **Pull Request로만** 반영합니다.
- 배포 기준 브랜치는 `main`입니다. (화면: `Final/`, 서버: `backend/`)

## 10. 확정이 필요한 것

- **기준값:** 당뇨식 탄수화물·당류 기준값, 저염 한 끼 770mg 확정 여부 (전문가 검토)
- **유동식:** 맑은·일반 유동식 정의와 영양 기준, 연하곤란식 단계 체계 → 확정 후 가족 프로필에 종류·단계 입력 추가
- **알레르기:** 프로필의 넓은 분류(견과류·갑각류)를 구체 항목으로 나눌지, 정책이 없는 알레르기(돼지고기·토마토 등) 처리
- **정량:** 어린이·노인 분량 환산 기준
