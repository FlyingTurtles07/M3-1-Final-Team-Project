보조 1_3 # 추적 가능한 가족별 식재료 필터 및 레시피 추천 규칙 v1.0

- 문서 목적: 법정 알레르기 표시 기준과 과학적 위험 관리 원칙을 분리하면서, 가족 구성원별 식재료 선택 및 레시피 추천에 적용할 수 있는 추적 가능한 판정 규칙을 정의한다.
- 적용 대상: 식재료 검색, 가공식품 선택, 레시피 생성, 레시피 수정, 가족 공동 식사 추천
- 판정 원칙: 근거 우선, 개인별 적용, 불확실성 보존, 실패 시 안전 우선, 판정 이력 기록
- 운영 상태: 설계 단계. 전문가 검토 및 테스트 완료 전에는 운영 판정을 확정하지 않는다.

## 1. 핵심 설계 원칙

### 1-1. 서로 다른 판단 체계를 분리한다

① 법정 표시 기준(LAW)

국내 관련 법령 및 고시에 따라 알레르기 유발물질의 표시 대상과 적용 조건을 판정한다. 법정 표시 기준은 법적 표시 의무를 판단하는 기준이며, 개인의 섭취 안전성을 직접 보증하는 기준이 아니다.

② 과학적 위험 관리(SAFETY)

원재료 정보의 불완전성, 교차접촉 가능성, 제품별 정보의 신뢰도, 표시 문구의 모호성 등을 평가한다. 이는 식품 표시 의무 판정과 별도의 위험 관리 절차로 운영한다.

③ 가족별 회피 규칙(PROFILE)

각 가족 구성원이 알레르기 또는 개인적 사유로 피해야 하는 식품을 설정한다. 법정 표시 대상에 포함되지 않는 식품도 개인 회피 대상으로 등록할 수 있다.

④ 레시피 추천(RECIPE)

위 세 가지 판단 결과를 통합해 특정 가족 구성원에게 레시피를 추천할 수 있는지 결정한다. 추천 결과에는 사용한 규칙, 근거, 확인하지 못한 정보가 함께 기록되어야 한다.

### 1-2. 금지할 판정 방식

- 법정 표시 대상이 아니라는 이유만으로 안전하다고 판정하지 않는다.
- 제품에 알레르기 표시가 없다는 이유만으로 해당 물질이 없다고 추정하지 않는다.
- 원재료 정보가 없거나 판독이 불확실한 경우 자동으로 통과시키지 않는다.
- '견과류', '생선', '해산물' 같은 포괄적인 단어만으로 서로 다른 식품을 무조건 동일하게 취급하지 않는다.
- 가족 구성원 한 명의 회피 조건을 다른 구성원에게 자동 적용하지 않는다.
- AI가 생성한 설명이나 추정만으로 원재료 포함 여부를 확정하지 않는다.
- PASS를 의학적 안전 보증 또는 알레르기 반응이 발생하지 않는다는 의미로 사용하지 않는다.

## 2. 법정 표시 기준 데이터(LAW)

### 2-1. 기준 출처

- 출처 기관: 식품의약품안전처
- 기준 문서: 「식품등의 표시기준」 식약처 고시 제2026-37호, 2026년 5월 12일
- 관련 법령: 「식품 등의 표시·광고에 관한 법률 시행규칙」 별표 2
- 공식 고시 확인: https://www.mfds.go.kr/brd/m_211/view.do?seq=14968
- 관련 법령 확인: https://www.law.go.kr/LSW/flDownload.do?bylClsCd=110201&flSeq=147344913&gubun=

법정 표시 기준 데이터는 적용 시점의 최신 법령 원문을 확인하고 버전별로 관리한다. 아래 목록은 설계의 기준 목록이며, 실제 운영 적용 전 해당 제품과 식품 유형에 적용되는 최신 규정을 재검증한다.

### 2-2. 국내 알레르기 유발물질 법정 표시 목록

1. 알류(가금류에 한함)
2. 우유
3. 메밀
4. 땅콩
5. 대두
6. 밀
7. 고등어
8. 게
9. 새우
10. 돼지고기
11. 복숭아
12. 토마토
13. 아황산류
14. 호두
15. 닭고기
16. 쇠고기
17. 오징어
18. 조개류(굴, 전복, 홍합 포함)
19. 잣

### 2-3. 법정 조건을 별도 관리한다

- 아황산류: 최종 제품에 이산화황이 1kg당 10mg 이상 함유된 경우라는 관련 조건을 별도로 관리한다. 단순히 '아황산'이라는 단어가 발견되었다는 이유만으로 법정 표시 조건 충족 여부를 확정하지 않는다.
- 알류: 가금류의 알이라는 법정 범위를 유지한다.
- 조개류: 법정 범위와 제품의 실제 원재료 정보를 구분한다. 모든 해산물을 조개류로 간주하지 않는다.
- 추출 성분 및 가공 원료: 원재료 자체뿐 아니라 관련 법령에서 규정한 추출 성분 등의 적용 범위를 확인한다.
- 적용 예외, 표시 방법, 식품 유형별 요건: 법령 원문에서 확인하며, 확인되지 않은 예외를 임의로 추가하지 않는다.

법정 목록은 `LEGAL_STANDARD` 데이터로 저장하고, 개인 회피 목록이나 과학적 위험 평가 데이터와 합치지 않는다.

## 3. 과학적 위험 관리 데이터(SAFETY)

다음 항목은 법정 표시 대상 목록이 아니라 위험 관리 절차에서 사용하는 평가 항목이다.

### 3-1. 원재료 정보의 신뢰도

- VERIFIED: 제조사 또는 제품 포장 등 확인 가능한 근거로 원재료 정보를 검증함
- PARTIAL: 일부 원재료 또는 하위 원재료만 확인함
- AMBIGUOUS: OCR 오류, 모호한 명칭, 불명확한 복합 원재료 등이 있음
- UNKNOWN: 확인 가능한 정보가 부족함
- STALE: 제품 변경 가능성에 비해 정보가 오래됨

### 3-2. 교차접촉 정보

- DECLARED: 교차접촉 관련 주의 문구 또는 관련 정보가 확인됨
- NOT_DECLARED: 확인한 자료에 해당 문구가 없음
- UNKNOWN: 관련 정보 자체를 확인하지 못함

`NOT_DECLARED`는 교차접촉이 없다는 뜻이 아니다. 제조 공정, 조리 도구, 작업 공간 등에 대한 확인 수준을 별도로 기록한다.

### 3-3. 위험 관리 원칙

- 제품별 실제 원재료와 하위 원재료를 확인한다.
- 원재료 정보와 교차접촉 정보를 서로 다른 필드로 저장한다.
- 불확실한 명칭은 동의어 사전만으로 확정하지 않고 추가 확인 대상으로 분류한다.
- 과학적 근거가 없는 임의의 위험 점수나 임계값을 만들지 않는다.
- 정량적 위험 평가를 적용하려면 대상 물질, 측정 단위, 노출량, 적용 가능한 기준 및 근거를 별도로 검증한다.
- 위험을 정량적으로 평가할 수 없는 경우 점수로 안전성을 가장하지 않고 NEEDS_REVIEW를 사용한다.

## 4. 가족 구성원별 회피 프로필(PROFILE)

가족 구성원별 프로필은 다음 필드를 가진다.

- `member_id`: 구성원 식별자
- `avoidance_item_id`: 회피 식품 식별자
- `avoidance_type`: 회피 사유 유형
- `severity_or_policy`: 사용자가 설정한 회피 정책 또는 의료진과 확인한 지침
- `effective_from`: 적용 시작일
- `effective_to`: 적용 종료일 또는 미설정
- `source_type`: 사용자 입력, 의료진 지침, 확인된 문서 등
- `source_reference`: 근거 자료 식별자
- `updated_at`: 마지막 수정 시각
- `profile_version`: 프로필 버전

회피 사유 유형은 최소한 다음처럼 구분한다.

- `ALLERGY`: 알레르기 관련 회피
- `PERSONAL_AVOIDANCE`: 개인 취향 또는 개인적 회피
- `OTHER_RESTRICTION`: 사용자가 별도로 설정한 기타 제한

개인 회피 목록은 법정 표시 목록과 별도로 저장한다. 예를 들어 사용자가 아몬드, 캐슈너트, 참깨 등을 피하도록 설정할 수 있지만, 이 설정만으로 해당 식품을 국내 법정 표시 목록에 추가하지 않는다.

## 5. 식재료 및 제품 데이터 구조

각 식재료 또는 가공식품은 다음 정보를 관리한다.

- `item_id`: 식재료 또는 제품 식별자
- `item_name`: 표시명
- `ingredient_text`: 확인된 원재료 표시 원문
- `subingredients`: 하위 원재료 정보
- `detected_allergens`: 확인된 알레르기 유발물질
- `detection_method`: 수동 확인, OCR 추출, 제조사 정보 등
- `verification_status`: VERIFIED, PARTIAL, AMBIGUOUS, UNKNOWN, STALE
- `cross_contact_status`: DECLARED, NOT_DECLARED, UNKNOWN
- `evidence_id`: 근거 자료 식별자
- `evidence_date`: 근거 자료 확인일
- `product_version`: 제품 정보 버전
- `reviewer`: 검토자 또는 검토 주체
- `review_status`: 검토 상태

제품 포장 이미지에서 OCR로 추출한 정보는 원문과 추출 결과를 모두 보관한다. OCR 결과를 자동 확정된 제품 정보와 동일하게 취급하지 않는다.

## 6. 동의어 및 식품 명칭 매칭 규칙

동의어 사전은 식품 이름을 찾는 보조 도구이며, 최종 안전 판정을 단독으로 결정하는 도구가 아니다.

각 동의어 항목은 다음 정보를 가진다.

- `alias_id`
- `alias_text`
- `canonical_item_id`
- `match_type`: EXACT, APPROVED_SYNONYM, AMBIGUOUS
- `scope`
- `evidence_id`
- `review_status`
- `version`

판정 규칙:

- 정확히 일치하는 식품명은 등록된 정규 식품명과 연결한다.
- 검토가 완료된 동의어만 승인된 매칭으로 사용한다.
- 여러 의미가 가능한 표현은 AMBIGUOUS로 처리한다.
- '콩', '견과류', '생선', '해산물'처럼 범위가 넓은 단어는 구체적인 식품을 자동 확정하지 않는다.
- 복합 원재료의 세부 성분을 확인할 수 없으면 누락된 정보를 기록하고 추가 확인한다.
- 부정 표현이나 주의 문구를 일반 원재료명과 혼동하지 않도록 문맥을 확인한다.

## 7. 판정 상태 정의

### PASS
필수 확인 절차가 완료되었고, 확인된 정보에서 해당 구성원의 회피 대상이 발견되지 않았으며, 미해결된 필수 정보가 남아 있지 않은 상태다. 이는 규칙 기반 추천 가능 상태이며 안전 보증이 아니다.

### BLOCKED
해당 구성원의 회피 대상이 실제 원재료 또는 확인된 성분에 포함된 것이 확인되어 추천에서 제외하는 상태다.

### NEEDS_REVIEW
원재료 누락, 모호한 명칭, 불완전한 하위 원재료, 교차접촉 정보 부족 또는 근거 미확인 등으로 현재 정보만으로 통과 판정을 내릴 수 없는 상태다.

### SYSTEM_ERROR
데이터베이스 오류, 규칙 엔진 오류, 필수 데이터 조회 실패 등으로 판정 절차가 정상 완료되지 않은 상태다.

상태의 의미는 사용자에게 명확하게 설명한다. NEEDS_REVIEW와 SYSTEM_ERROR를 PASS로 변환하는 자동 예외 처리를 금지한다.

## 8. 추적 가능한 판정 절차

### 8-1. 입력 데이터 검증

식재료 또는 제품 정보, 대상 가족 구성원, 프로필 버전, 적용 규칙 버전이 존재하는지 확인한다.

필수 데이터 조회에 실패하면 SYSTEM_ERROR로 종료한다.

### 8-2. 법정 표시 기준 대조

원재료 및 하위 원재료에서 확인된 물질을 법정 목록과 대조한다.

이 단계에서는 법정 표시 대상과 해당 조건의 충족 여부만 기록한다. 법정 목록에 없다는 이유만으로 개인 회피나 위험 관리 검토를 생략하지 않는다.

### 8-3. 가족별 회피 조건 대조

확인된 식품 및 물질을 해당 구성원의 활성 회피 프로필과 대조한다.

확정된 회피 대상이 발견되면 BLOCKED로 처리하고, 어떤 프로필 규칙과 원재료 근거가 일치했는지 기록한다.

### 8-4. 위험 관리 정보 검토

원재료 정보, 하위 원재료, 교차접촉 정보, 근거의 최신성 및 판독 신뢰도를 확인한다.

필수 정보가 불완전하거나 모호하면 NEEDS_REVIEW로 처리한다. 교차접촉 관련 정보가 확인되지 않은 경우 이를 '교차접촉 없음'으로 해석하지 않는다.

### 8-5. 최종 판정

우선순위는 다음과 같다.

1. 필수 처리 과정의 오류가 발생하면 SYSTEM_ERROR
2. 오류가 없고 회피 대상 포함이 확인되면 BLOCKED
3. 회피 대상 포함은 확인되지 않았지만 필수 정보가 불완전하면 NEEDS_REVIEW
4. 필수 검토가 완료되고 미해결된 차단 사유나 필수 확인 사항이 없으면 PASS

각 판정에는 상태뿐 아니라 판정 이유, 근거 식별자, 적용 규칙 버전 및 확인 시각을 기록한다.

## 9. 레시피 추천 통합 규칙

레시피는 재료 목록 전체를 기준으로 평가한다. 재료를 하나씩 평가한 결과를 단순히 평균 내거나, 일부 재료의 PASS로 다른 재료의 불확실성을 상쇄하지 않는다.

- 하나 이상의 필수 처리 오류가 발생하면 레시피 판정을 중단하고 SYSTEM_ERROR를 반환한다.
- 오류가 없고 하나 이상의 재료가 BLOCKED이면 해당 구성원에게 레시피를 추천하지 않는다.
- BLOCKED는 없지만 하나 이상의 재료가 NEEDS_REVIEW이면 추천을 보류하고 확인이 필요한 재료를 안내한다.
- 모든 필수 재료가 PASS일 때만 규칙 기반 추천 가능 상태로 표시한다.

### 가족 공동 식사 규칙

- 가족 구성원마다 별도로 판정한다.
- 공동 레시피는 함께 식사할 모든 대상 구성원의 조건을 충족해야 한다.
- 특정 구성원에게 BLOCKED인 재료를 임의로 포함하지 않는다.
- 대체 재료를 제안할 때에도 해당 대체 재료를 처음부터 다시 검증한다.
- 조리 도구, 작업대, 보관 용기 등 조리 과정의 교차접촉 위험은 재료 목록 판정과 분리해 확인한다.
- 공동 조리가 확인되지 않은 위험을 해결했다고 가정하지 않는다.

## 10. 판정 이력 및 근거 추적

모든 판정은 재현 가능한 기록으로 저장한다.

- `decision_id`: 판정 고유 식별자
- `target_type`: INGREDIENT, PRODUCT, RECIPE
- `target_id`: 판정 대상 식별자
- `member_id`: 대상 가족 구성원
- `profile_version`: 적용한 가족 프로필 버전
- `legal_standard_version`: 적용한 법정 기준 버전
- `safety_rule_version`: 적용한 위험 관리 규칙 버전
- `ingredient_data_version`: 사용한 원재료 데이터 버전
- `decision_status`: PASS, BLOCKED, NEEDS_REVIEW, SYSTEM_ERROR
- `reason_codes`: 판정 사유 코드 목록
- `matched_items`: 일치한 식품 또는 물질
- `unresolved_items`: 확인이 필요한 항목
- `evidence_ids`: 판정에 사용한 근거 식별자
- `decided_at`: 판정 시각
- `review_status`: 검토 상태
- `reviewer`: 검토자
- `supersedes_decision_id`: 이전 판정 식별자(해당하는 경우)

기존 판정 기록을 덮어쓰지 않는다. 법정 기준, 가족 프로필, 제품 정보 또는 규칙이 변경되면 새 판정을 생성하고 이전 판정과 연결한다.

## 11. 판정 사유 코드 예시

- `LAW_MATCH_CONFIRMED`: 법정 표시 대상과 관련된 원재료 확인
- `PROFILE_MATCH_CONFIRMED`: 가족별 회피 대상 확인
- `SUBINGREDIENT_MISSING`: 하위 원재료 정보 부족
- `OCR_AMBIGUOUS`: OCR 판독 불확실
- `PRODUCT_DATA_STALE`: 제품 정보 최신성 부족
- `CROSS_CONTACT_DECLARED`: 교차접촉 관련 문구 확인
- `CROSS_CONTACT_UNKNOWN`: 교차접촉 정보 미확인
- `SULFITE_CONDITION_UNVERIFIED`: 아황산류 관련 조건 미확인
- `ALIAS_AMBIGUOUS`: 식품명 매칭 모호
- `EVIDENCE_MISSING`: 판정 근거 부족
- `DATABASE_ERROR`: 데이터 조회 오류
- `RULE_ENGINE_ERROR`: 규칙 엔진 오류

사유 코드는 법정 의무의 존재, 실제 성분의 확인, 위험 관리상의 불확실성을 구분해서 사용한다.

## 12. 필수 검증 테스트

T-01. 우유가 원재료로 확인되고 대상 구성원이 우유 회피를 설정한 경우 → BLOCKED

T-02. 법정 표시 목록에 포함되지 않는 식품이라도 구성원이 개인 회피 대상으로 설정한 경우 → 해당 프로필 규칙에 따라 BLOCKED

T-03. OCR 결과에서 원재료명이 모호하게 판독된 경우 → NEEDS_REVIEW

T-04. 복합 원재료의 하위 성분을 확인할 수 없고 해당 정보가 판정에 필요한 경우 → NEEDS_REVIEW

T-05. 아황산류 관련 단어만 발견되고 최종 제품의 관련 조건을 확인할 수 없는 경우 → 법정 조건 충족 여부 미확정, NEEDS_REVIEW

T-06. 교차접촉 주의 문구가 확인된 경우 → 해당 정보를 별도 기록하고 구성원별 정책에 따라 평가. 근거 없이 PASS로 확정하지 않음

T-07. '콩'이라는 표현만 있고 구체적인 식품을 식별할 수 없는 경우 → NEEDS_REVIEW

T-08. 필수 제품 데이터베이스 조회가 실패한 경우 → SYSTEM_ERROR

T-09. 제품 원재료와 하위 원재료, 필요한 위험 관리 정보 및 가족별 회피 조건을 모두 검토한 경우 → 미해결 사항이 없을 때만 PASS

T-10. 가족 구성원 A는 땅콩 회피, 구성원 B는 우유 회피를 설정한 경우 → 구성원별로 독립적인 결과 생성

T-11. 레시피의 여러 재료 중 한 재료가 NEEDS_REVIEW인 경우 → 전체 레시피 추천 보류

T-12. 대체 재료를 적용한 경우 → 대체 재료를 포함해 전체 레시피 재검증

## 13. 운영 및 변경 관리

- 법정 기준 변경 시 법정 데이터 버전을 갱신하고 영향을 받는 판정을 재검토한다.
- 제조사 원재료 정보 변경 시 해당 제품을 참조하는 식재료 및 레시피를 재검토한다.
- 동의어 사전 변경은 검토 이력을 남기고 기존 판정에 소급 적용하지 않는다.
- 새로운 판정 규칙은 테스트 케이스 통과와 검토 완료 후 운영 활성화한다.
- 근거가 없는 규칙, 미검증 규칙, 오류 처리 미완료 규칙은 운영 비활성 상태로 유지한다.
- 규칙 운영 상태는 ENABLED, DISABLED, UNDER_REVIEW로 구분한다.

## 14. 서비스 고지

이 필터는 확인 가능한 식품 정보와 등록된 회피 조건에 근거하여 식재료 선택을 지원하는 도구다. 의료적 진단이나 알레르기 반응이 발생하지 않는다는 보증을 제공하지 않는다.

제품 표시, 제조 공정, 교차접촉 및 조리 환경에 따라 실제 위험이 달라질 수 있다. 정보가 불완전하거나 사용자의 알레르기 관리 지침과 충돌하는 경우에는 자동 추천을 보류하고 제품 제조사 또는 적절한 의료 전문가에게 확인하도록 안내한다.

## 15. 최종 적용 원칙

법정 표시 기준은 법적 표시 요건을 판단하는 데 사용한다. 과학적 위험 관리는 정보의 불확실성과 잠재적 노출 위험을 다루는 데 사용한다. 가족별 회피 프로필은 개인의 선택 조건을 반영하는 데 사용한다.

세 체계는 서로 대체하지 않으며, 각각의 근거와 버전을 유지한 상태에서 최종 레시피 추천 단계에서만 통합한다.

운영 적용 전에는 최신 법령 원문 확인, 제품별 원재료 데이터 검증, 전문가 검토, 테스트 케이스 실행을 완료해야 한다.
