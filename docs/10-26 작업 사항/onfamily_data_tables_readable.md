# 레시피 추천 데이터 표 설계 (팀 공유용, 쉬운 버전)

작성: 김지숙 (backend-infra) / 2026-10-26
근거: 레시피 추천 정책 22종, 레시피 지침 v0.1
- 이 문서는 **표마다 어떤 항목이 들어가는지, 예시 값은 무엇인지** 를 보여 줍니다.
- 칸 이름(영문)은 개발에서 쓰는 이름입니다. 같은 이름이 `recipe_tables.sql` 에 있습니다.
- `id`, 만든 시각 같은 기본 칸은 생략했습니다.
- 예시 값 중 **[ ]** 로 표시한 것은 실제 자료(식약처 등)에서 확인해 채울 값입니다. 임의로 만들지 않았습니다.

## 2. A. 기준 자료

### 2-1. 정책 보관함 (`policy_versions`)

- **무슨 표?** 정책 22종, 공통 규칙, 레시피 지침을 버전별로 통째로 보관합니다.
- **왜 필요?** 정책이 바뀌어도 "이 레시피는 어느 버전으로 만들었는지" 알 수 있습니다.
- **누가 채움?** 정책 파일이 바뀔 때 개발자(또는 자동).

| 항목 | 칸 이름 | 설명 | 예시 |
|---|---|---|---|
| 정책 코드 | code | 정책 번호 | AL-03, NA-02, COMMON |
| 버전 | version | 정책 버전 | 2026-10-26 |
| 본문 | content | 그때의 정책 전체 글 | [AL-03] 땅콩 알레르기 … |
| 지문 | content_hash | 본문이 바뀌었는지 확인용 | (자동 계산) |

### 2-2. 기준값·설정표 (`rule_settings`)

- **무슨 표?** 판정에 쓰는 수치와 설정. **확정 여부를 함께** 적습니다.
- **왜 필요?** 임시값을 쓴 결과인지 나중에 알 수 있고, 보류된 값은 통과가 아니라 "확인 필요"로 처리됩니다.

| 항목 | 칸 이름 | 설명 | 예시 |
|---|---|---|---|
| 기준 이름 | key | 무엇의 값인지 | sodium_daily_mg |
| 값 | value | 숫자나 설정 (보류면 비움) | 2300 |
| 단위 | unit | | mg |
| 확정 상태 | status | confirmed(확정) / provisional(임시) / on_hold(보류) | provisional |
| 관련 정책 | policy_code | 어느 정책이 쓰는지 | NA-02 |
| 출처 | source | 근거 자료 | 한국인 영양소 섭취기준 |

예시 행

| key | value | status | policy_code |
|---|---|---|---|
| sodium_daily_mg | 2300 | confirmed | NA-02 |
| sodium_meal_mg | 770 | **provisional** (임시값, 전문가 확정 필요) | NA-02 |
| carb_limit_meal_g | (비움) | **on_hold** | DM-01 |
| sugar_limit_meal_g | (비움) | **on_hold** | DM-01 |
| round_g | 5 | provisional (팀 결정안) | QT-01 |
| round_ml | 10 | provisional (팀 결정안) | QT-01 |

- **누가 채움?** 팀(고시 확인 후 입력).

### 2-4. 재료 사전 (`ingredients`)

- **무슨 표?** 레시피에 쓸 수 있는 재료의 **정확한 이름** 목록. 정책은 "이름이 정확히 일치하는 항목만" 쓰라고 합니다.
- **누가 채움?** 팀. 처음에는 흔한 재료 100~200개로 시작하는 것을 권합니다.

| 항목 | 칸 이름 | 설명 | 예시 |
|---|---|---|---|
| 검색 이름 | search_name | 정확히 일치시킬 이름 (중복 불가) | 두부 |
| 화면 이름 | display_name | 사용자에게 보이는 이름 | 두부 |
| 식약처 식품 코드 | kfda_food_code | 식약처 영양 DB의 코드 | [식약처 DB 코드] |
| 이름 확인 상태 | match_status | confirmed(확인) / review(검토 필요) | confirmed |
| 나트륨 주의 | sodium_caution | 간장·된장·젓갈 등 | 아니오 |
| 첨가당 | added_sugar | 설탕·꿀·시럽 등 | 아니오 |
| 가공품 | is_processed | 원재료표 확인이 필요한 가공품 | 아니오 |

| search_name | sodium_caution | added_sugar | is_processed |

| 두부 | 아니오 | 아니오 | 아니오 |

### 2-5. 재료 별칭표 (`ingredient_aliases`)

- **무슨 표?** 같은 재료의 다른 이름. **검색 후보로만** 쓰고, 별칭만으로는 판정하지 않습니다. (AL-01 등)

| 항목 | 칸 이름 | 예시 |
|---|---|---|
| 별칭 | alias | 계란 |
| 연결된 재료 | ingredient_id | 달걀 |
| 확인 상태 | status | review (검토 필요) |

### 2-6. 재료·알레르기 연결표 (`ingredient_allergens`)

- **무슨 표?** 어떤 재료가 어떤 알레르기 항목과 관련 있는지.
- **왜 필요?** 알레르기 구성원 레시피에서 해당 재료를 걸러 냅니다(BLOCKED).

| 항목 | 칸 이름 | 설명 | 예시 |
|---|---|---|---|
| 재료 | ingredient_id | | 두부 |
| 알레르기 항목 | allergen_item_id | | 대두 |
| 관계 | relation | contains(포함) / derivative_possible(파생 가능) / cross_contact_note(교차오염 주의) | contains |
| 확인 상태 | status | confirmed / review | confirmed |

예시 행

| 재료 | 알레르기 항목 | 관계 |
|---|---|---|
| 두부 | 대두 | 포함 |
| 간장 | 대두 | 파생 가능 (원재료표 확인 필요) |
| 간장 | 밀 | 파생 가능 (원재료표 확인 필요) |
| 땅콩 | 땅콩 | 포함 |
| 달걀 | 알류 | 포함 |

### 2-7. 정량 기준표 (`ingredient_portions`)

- **무슨 표?** 분량을 정하는 기준. **분량은 AI가 아니라 엔진이** 이 표로 채웁니다. (QT-01)

| 항목 | 칸 이름 | 설명 | 예시 |
|---|---|---|---|
| 재료 | ingredient_id | | 두부 |
| 기준 종류 | basis | exchange_unit(교환단위량) / serving_reference(1회 섭취참고량) / edible_ratio(가식부 비율) / piece_weight(개당 중량) / discard_rate(폐기율) | serving_reference |
| 값 | value | g 또는 비율 | [식약처 값] |
| 출처 | source | | 식약처 1회 섭취참고량 |
| 확인 상태 | status | confirmed / review | review |

### 2-8. 영양 정보 (`food_nutrients`)

- **무슨 표?** 식약처 식품영양성분 DB에서 받아 온 **100g당** 영양 수치의 보관본. 호출 결과를 캐시합니다. (NA-01)

| 항목 | 칸 이름 | 예시 |
|---|---|---|
| 재료 | ingredient_id | 두부 |
| 열량(kcal) | energy_kcal | [식약처 값] |
| 탄수화물(g) | carbohydrate_g | [식약처 값] |
| 당류(g) | sugars_g | [식약처 값] |
| 식이섬유(g) | fiber_g | [식약처 값] |
| 나트륨(mg) | sodium_mg | [식약처 값] |
| 출처 | source | 식약처 식품영양성분 DB |
| 받아 온 시각 | fetched_at | [날짜] |

데이터가 없으면 "데이터 없음"으로 처리해서 NEEDS_REVIEW가 됩니다.

### 2-9. 재료 근거 태그 (`ingredient_tags`)

- **무슨 표?** 당뇨식 설명이나 대체 제안에 쓰는 태그. **판정을 통과로 바꾸지 못합니다.** (DM-02) 사람이 확정한 것만 씁니다.

## 3. B. 가족 건강 기록 (`member_health_records`)

- 날짜별로 **추가만** 하는 기록이고, 내용은 암호화됩니다. 자세한 규칙은 「가족 건강 기록(이력) 설계」 문서를 보세요.
- 암호화된 내용 안에는 이런 항목이 들어갑니다.

| 항목 | 설명 | 예시 |

### 4-4. 안전 검사 결과 (`safety_checks`)

| 항목 | 칸 이름 | 설명 | 예시 |
|---|---|---|---|
| 변형 | variant_id | 어느 구성원의 변형인지 | 민준의 닭도리탕 |
| **판정** | status | 아래 4가지 중 하나 | PASS |
| 엔진 버전 | engine_version | | 0.1 |
| 사용한 정책 버전 | policy_snapshot | | |
| 현재 유효 | is_current | 변형당 **하나만** 가능 | 예 |
| 다시 검사 필요 | stale_at | 프로필이 바뀐 시각. 비어 있어야 화면에 표시 | (비움) |

판정 4가지와 화면 문구 (공통 규칙)

| 판정 | 뜻 | 화면 |
|---|---|---|
| PASS | 확인된 정보에서 회피 대상이 없고 필수 미확인 정보가 없음 (안전 보증은 아님) | "안전 검사 완료" |
| BLOCKED | 회피 대상이 확인됨 | 그 레시피를 빼고 다시 생성 |
| NEEDS_REVIEW | 정보 부족·모호 | "확인이 필요해요" |
| SYSTEM_ERROR | 조회·엔진 오류 | (오류 처리) |

우선순위: SYSTEM_ERROR > BLOCKED > NEEDS_REVIEW > PASS

### 4-5. 판정 근거 (`safety_check_items`)

- 화면에는 보이지 않고 **서버에서만** 읽습니다. (세부 사유는 노출하지 않는다)

| 항목 | 칸 이름 | 예시 |
|---|---|---|
| 어느 검사 | check_id | |
| 정책 | policy_code | NA-02 |
| 무엇을 봤나 | subject_type / subject_ref | nutrient / 나트륨 |
| 결과 | result | NEEDS_REVIEW |
| 이유 코드 | detail_code | NO_AMOUNT |
| 계산값 / 한도 | value / limit_value | [엔진 계산값] / 770 |

## 5. 예시로 따라가 보기

시험 가족: 아빠(저염식), 엄마(당뇨식), 민준(땅콩 알레르기), 할머니(저염식 + 일반 유동식)

1. **정책 고르기:** 건강 기록을 읽고 아빠 NA-01~04, 엄마 DM-01~04, 민준 AL-03, 할머니 NA-01~04 + LQ-02 를 고릅니다. QT-01 은 항상 포함합니다.
2. **Gemini 제안:** 재료와 조리법만 나옵니다. 분량과 판정은 없습니다.
3. **재료 이름 확인:** `재료 사전` 의 검색 이름과 정확히 일치하는지 봅니다. 일치하지 않으면 NEEDS_REVIEW입니다.
4. **알레르기 확인:** 민준의 레시피에 땅콩과 연결된 재료가 있으면 BLOCKED, 간장처럼 "파생 가능"인데 원재료표를 확인할 수 없으면 NEEDS_REVIEW입니다.
5. **분량 채우기:** `정량 기준표` 로 엔진이 채웁니다.
6. **영양 계산:** `영양 정보` × 분량을 합산하고(4인분 합계 ÷ 4) `기준값·설정표` 와 비교합니다. 보류된 기준은 NEEDS_REVIEW입니다.
7. **저장:** 레시피, 구성원별 변형, 안전 검사 결과, 판정 근거를 저장합니다.
8. **화면:** 판정 상태만 보여 줍니다.
