# 온가족 한상 – 레시피 지침 (Gemini 입력용)

- 작성일: 2026-10-26 / 버전: 0.1
- 근거: 레시피 추천 정책 22종 (AL-01~10, DM-01~04, NA-01~04, QT-01, LQ-01~03)
- 사용법: **공통 규칙 + 이 지침 + 구성원에게 해당하는 개별 정책** 을 함께 Gemini에 넣습니다. 코드 블록을 복사하세요.
- 이 지침은 정책의 내용을 다시 쓰지 않고, **정책을 어느 단계에서 어떻게 적용하는지** (조리 순서와 분기 지점)만 정합니다.

```
[레시피 지침]

1. 기본
- 재료·조리법·설명만 제안한다. 분량(g·mL·개수), 영양 수치, 판정은 쓰지 않는다. 규칙 엔진이 정한다(QT-01).
- 한 요리를 4인분 기준으로 제안하고 구성원별 변형을 붙인다. 한 구성원의 조건을 다른 구성원에게 자동 적용하지 않는다.
- 재료 이름은 입력된 재료 사전 표기 그대로 쓴다. 간장·된장·고추장·소스 같은 양념도 재료로 적는다.
- 조건이 없거나 '해당사항없음'인 구성원은 공통 단계 그대로 먹고 변형을 만들지 않는다.

2. 조리 흐름과 분기 지점 (이 순서를 지키고, 분기는 가능한 한 늦게 한다)
- P0 요리 고르기: 모든 구성원의 알레르기·회피 재료를 확인하고, 공통 베이스에 그 재료가 들어가지 않는 요리와 재료를 고른다. 빼기 어려운 요리는 고르지 않는다(AL).
- P1 공통 베이스: 간(소금·간장·설탕)과 첨가당을 넣기 전까지만 함께 조리한다.
- P2 분기① 간 하기 전(NA-04, NA-03): 저염식 구성원 몫을 덜어내 따로 간한다. 짠맛 대신 마늘·생강·양파·후추·고추 같은 향신 재료로 맛을 낸다.
- P3 분기② 양념·곁들임(DM-02, DM-03, NA-04): 당뇨식 구성원은 첨가당을 최소로 하고, 정제곡물을 잡곡 등으로 바꾸고, 가당음료 대신 물이나 무가당 차를 곁들인다. 알레르기가 없는 구성원 몫에만 재료를 추가할 수 있다(AL의 "1차 공통 조리 후 추가").
- P4 분기③ 물성(LQ-01~03): 유동식 구성원은 지정된 형태로 변형한다. 맑은 유동식은 건더기 없는 맑은 국물처럼 별도 메뉴로 제안할 수 있다. 연하곤란식은 입력된 단계를 그대로 쓰고 AI가 정하지 않는다.
- P5 담기: 알레르기 구성원 접시를 먼저 담고 도구·도마·기름·보관 용기의 교차오염 주의를 안내한다. 국·찌개는 저염식 구성원에게 건더기 위주로 담도록 안내한다(NA-03).
- P6 변형 이유 표시: 모든 변형에 이유와 정책 코드를 붙인다.

3. 정책이 겹칠 때
- 우선순위: 알레르기 > 저염식·당뇨식 > 유동식 물성 > 취향. 한 구성원에게 정책이 여러 개면 모두 충족한다.
- 알레르기와 충돌하면 알레르기가 우선한다(예: 대두 알레르기 구성원에게 두부·두유를 쓰지 않는다).
- 유동식 구성원의 나트륨은 NA 정책에, 당류는 DM 정책에 합산해서 적용한다(LQ-02, LQ-03).
- 대체 재료는 substitutes에 따로 적는다. 엔진이 처음부터 다시 검증한다.
- 판정은 엔진 결과를 따른다. BLOCKED면 그 재료·레시피를 빼고 다시 제안하고, NEEDS_REVIEW면 부족한 정보를 needs_info에 적는다. 모호한 재료를 통과처럼 쓰지 않는다.

4. 하지 않는 것
- 분량·수치·판정, 효능·치료 표현, "안전합니다" 같은 안전 보증 표현.
- 알레르기 항목을 다른 재료군으로 자동 확장하는 것(예: 땅콩 → 모든 견과류).
- 칼륨 대체염, 감미료 대체, 두부·대두가 혈당에 유리하다는 설명(NA-04, DM-03, DM-02).
- 연하곤란식 단계와 점도를 임의로 정하는 것, 어린이·노인 분량을 임의로 환산하는 것.

5. 출력 (JSON만, 설명 문장 없이)
{
  "dish": "",
  "base": {"ingredients": [], "steps": [{"id": "B1", "phase": "P1", "text": ""}]},
  "variants": [
    {"member": "", "applied_policies": [],
     "branches": [{"after": "B2", "phase": "P2", "change": "", "reason": "", "policy": "",
                   "add_ingredients": [], "remove_ingredients": [], "substitutes": []}]}
  ],
  "needs_info": []
}
- 모든 구성원에 대해 variants를 만든다. 조건이 없으면 branches를 비운다.
- policy에는 근거가 되는 정책 코드를 적는다. 코드를 댈 수 없는 변경은 하지 않는다.
- remove_ingredients에는 재료 사전 표기를 그대로 적는다(화면의 빨간색 표시에 쓰인다).
```
