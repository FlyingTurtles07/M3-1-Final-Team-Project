## 1. 프로젝트 요약

**Prompt Camp to Academy**는 생성형 AI 입문자가 게임형 퀘스트와 1:1 스타 멘토 코칭으로 프롬프트 작성법을 체득하도록 돕는 웹 서비스입니다.

- **1단계 Prompt Camp**: 타이핑 부담이 적은 객관식·빈칸·드래그 퀘스트 5개로 프롬프트의 핵심 요소를 학습하고, 수료하면 **입교 티켓**을 받습니다.
- **2단계 Prompt Academy**: 제약조건 설계, 할루시네이션 팩트체크, 문서 가공 등 실전 퀘스트를 수행합니다.
- **1:1 프롬프트 튜닝 연구소**: 내 질문과 멘토가 튜닝한 질문의 답변을 **좌/우 분할**로 비교합니다.
- **3인 3색 멘토 + Long-term Memory**: 멘토가 나의 반복 실수를 기억하고 개인화 코칭을 합니다.

## 2. 배경 및 문제 정의

### 2.1 문제 상황 흐름

```text
[타깃] AI에 관심은 있으나 흰 검색창 앞에서 막막한 왕초보
   ↓
[상황] "보고서 써줘", "파이썬 알려줘"처럼 막연히 질문 → 뻔한 답변에 실망
   ↓
[현재 해결법] 유튜브/블로그 프롬프트 템플릿 복사·붙여넣기
   ↓
[한계] 내 상황에 맞게 수정하지 못함 (원리 미체득)
   ↓
[핵심 고통] 시작의 막막함 / 품질 실망 / 검증의 어려움
   ↓
[해결 방향] 쉬운 퀘스트 + 비포/애프터 비교 + 나를 기억하는 멘토
```

### 2.2 Pain Point 4가지

| # | Pain Point | 설명 |
| :-: | :--- | :--- |
| 1 | 시작의 공포 | 무엇을 입력할지 몰라 막연한 단답형 질문만 던짐 |
| 2 | 품질 저하와 포기 | 뻔한 답변을 받고 "AI 별거 없네" 하며 이탈 |
| 3 | 응용력 부족 | 복사한 치트키를 내 업무/일상에 맞게 못 바꿈 |
| 4 | 할루시네이션 취약 | AI의 그럴듯한 거짓말을 검증하지 못함 |

### 2.3 타깃 사용자

- **1차**: ChatGPT/Claude 등을 처음 접하거나 질문창 앞에서 막막한 완전 왕초보
- **2차**: 업무·학습 효율을 높이고 싶은 직장인, 대학생, 취업준비생

### 2.4 차별점

| 기존 방식 | 본 서비스 |
| :--- | :--- |
| 프롬프트 템플릿 복사 | 원리를 퀘스트로 체득 |
| 텍스트 강의/글 | 게임형 학습 + 즉각 채점 |
| 일회성 학습 | 취약점을 기억하는 지속 코칭 |
| 정보만 전달 | 취향에 맞는 멘토 페르소나 |

> 📝 **작성 필요**: 유사 서비스(프롬프트 교육 사이트, 챗봇 튜토리얼 등) 2~3개를 조사해 위 표에 실제 비교 대상으로 추가하세요.

## 4. 서비스 설계

### 4.1 성장 구조

```text
[멘토 선택] → [Prompt Camp: 퀘스트 5개] → [입교 티켓] → [Prompt Academy]
                                                     ├─ 실전 퀘스트
                                                     ├─ 1:1 튜닝 연구소
                                                     └─ 훈련 기록 / 배지
```

### 4.2 멘토 3인

| 멘토 | 콘셉트 | 말투 예시 | 코칭 스타일 |
| :--- | :--- | :--- | :--- |
| **차도혁** | 시크한 천재 선배 (츤데레) | "흥, 그렇게 질문하면 AI가 알 리가 없잖아. 내가 고쳐줄 테니 잘 봐." | 팩트 중심, 핵심을 찌르는 완벽주의 첨삭 |
| **유하린** | 비타민 아이돌 리더 | "우와! 첫 시도인데 정말 잘하셨어요! '조건' 하나만 넣으면 완벽해요!" | 칭찬과 격려로 자존감 유지 |
| **강태산** | 열정 에이스 교관 | "좋습니다 훈련생! 다음 퀘스트도 거침없이 돌파합시다!" | 높은 에너지, 명확한 단계별 지시 |

### 4.3 Prompt Camp 퀘스트 (5개)

| # | 퀘스트명 | 형태 | 학습 요소 | 채점 방식 |
| :-: | :--- | :--- | :--- | :--- |
| C1 | AI에게 정체성 선물하기 | 객관식 | 역할(Role) | 규칙 기반 |
| C2 | 목적을 말해주세요 | 빈칸 채우기 | 목적·맥락 | 규칙 기반 |
| C3 | 원하는 모양으로 받기 | 드래그앤드롭 | 출력 형식(표, 불릿 등) | 규칙 기반 |
| C4 | 세 조각 맞추기 | 객관식+빈칸 | 역할+목적+형식 조합 | 규칙 기반 |
| C5 | 입교 시험 | 짧은 문장 작성 | 종합 | **LLM(Evaluator)** |

> 왕초보 대상이므로 C1~C4는 LLM 호출 없이 규칙 기반으로 채점해 **비용과 지연을 줄입니다.** LLM은 C5, Academy, 연구소에서 사용합니다.

### 4.4 Prompt Academy 퀘스트

| # | 퀘스트명 | 학습 요소 | 내용 |
| :-: | :--- | :--- | :--- |
| A1 | 제약조건의 힘 | 제약(분량, 톤, 금지어) | 조건을 추가해 답변 통제하기 |
| A2 | 할루시네이션 사냥꾼 | 검증 | AI 답변 속 거짓 정보를 찾고 팩트체크 질문 작성 |
| A3 | 문서 요약·데이터 가공 | 복합 지시 | 긴 글을 요약하고 표로 정리하도록 지시 |
| A4 | 예시로 가르치기 | Few-shot | 예시를 제공해 원하는 스타일 유도 |
| A5 | 졸업 과제 | 실전 응용 | 본인의 실제 업무/일상 문제를 프롬프트로 해결 |

보상: 퀘스트 클리어 시 점수 + 배지 (예: 🏅 역할 마스터, 🥈 표형식 전문가, 🎯 팩트체커)

### 4.5 1:1 프롬프트 튜닝 연구소

1. 사용자가 평소 궁금한 질문을 자유롭게 입력 (추천 질문 원클릭 버튼 제공)
2. **좌측**: 원본 질문 → 기존 AI 답변
3. **우측**: 멘토가 튜닝한 프롬프트 → 고품질 답변
4. **하단**: 멘토의 1줄 코칭 (사용자의 과거 취약점 반영)
5. 튜닝된 프롬프트 **복사 버튼** 제공

### 5.2 채점 기준 (Evaluator)

| 요소 | 배점 | 판단 기준 |
| :--- | :-: | :--- |
| 역할(Role) | 25 | AI에게 구체적인 전문가/역할이 부여되었는가 |
| 맥락·목적(Context) | 25 | 대상, 상황, 목적이 드러나는가 |
| 제약조건(Constraint) | 25 | 분량, 톤, 범위, 금지 사항 등이 있는가 |
| 출력 형식(Format) | 25 | 표, 목록 등 결과 형태를 지정했는가 |

- Camp 단계에서는 **역할·맥락·형식**을 중심으로, 제약조건은 Academy부터 채점에 반영합니다.
- 출력은 항목별 점수, 빠진 요소 목록, 총점을 JSON으로 받습니다.

## 7. AI 설계

### 7.1 에이전트 구성

| 에이전트 | 역할 | 입력 | 출력 |
| :--- | :--- | :--- | :--- |
| **Evaluator Agent** | 프롬프트 진단·채점 | 사용자 프롬프트, 퀘스트 정보 | 요소별 점수, 빠진 요소, 총점 (JSON) |
| **Prompt Tuning Agent** | 프롬프트 재작성·결과 생성 | 원본 질문, 빠진 요소 | 튜닝 프롬프트, 원본 답변, 튜닝 답변 |
| **Persona Agent** | 멘토 말투 코칭 | 멘토 ID, 채점 결과, 취약점 메모리 | 1줄 총평 |

### 7.2 처리 흐름 (연구소 기준)

```text
사용자 질문
   ↓
Orchestrator → Memory 조회(취약점 Top 3)
   ├─ Evaluator: 빠진 요소 진단 ──┐
   ├─ Tuning: 프롬프트 재작성 ────┼→ (병렬)
   └─ 원본 질문 답변 생성 ────────┘
   ↓
Tuning 결과 답변 생성 → Persona: 멘토 코칭 생성
   ↓
결과 화면 출력 + Memory 갱신(빠진 요소 카운트 +1)
```

### 7.3 멘토 페르소나 System Prompt 구성 원칙

- 공통: 역할 정의 → 말투 규칙 → 금지 사항(과도한 비하·허위 칭찬 금지) → 출력 형식(**한 줄, 60자 내외**)
- 차도혁: 짧은 문장, 살짝 퉁명스럽지만 핵심은 정확히 짚음
- 유하린: 감탄사와 칭찬으로 시작하고 개선점은 "하나만" 제안
- 강태산: 존댓말 + 힘 있는 어조, 다음 행동을 명확히 지시
- 안전 규칙: 캐릭터를 유지하더라도 **채점 결과(점수·빠진 요소)는 왜곡하지 않음**

### 7.4 Long-term Memory

| 저장 항목 | 예시 | 활용 |
| :--- | :--- | :--- |
| 취약점 카운터 | `format_missing: 3`, `role_missing: 1` | 멘토 코칭에 반복 실수 언급 |
| 퀘스트 이력 | 퀘스트ID, 점수, 시도 횟수 | 진행도 표시, 재도전 안내 |
| 배지 | 역할 마스터 등 | 훈련 수첩 표시 |
| 선택 멘토 | 유하린 | 페르소나 유지 |

- 활용 예: *"OO님, 저번에도 형식을 깜빡하셨는데 이번엔 아주 잘 챙기셨네요!"*
- 프롬프트 주입 방식: 취약점 상위 3개와 최근 3회 점수를 요약해 Persona Agent 컨텍스트에 삽입

### 7.5 멀티모달 (확장)

- **MVP**: 멘토별 표정 이미지 3종(기본/성공/격려)을 사전 제작해 채점 결과에 따라 전환 (AI 생성 이미지 활용 가능)
- **확장**: 멘토 음성 TTS(FR-09)
- 필수 기술 요건은 **AI Agent + Long-term Memory**로 충족하며, 멀티모달은 추가 요소입니다.

### 7.6 AI 신뢰성·안전 대책

| 리스크 | 대응 |
| :--- | :--- |
| 채점 결과 불안정 | JSON 스키마 고정, temperature 낮게, 채점 기준을 프롬프트에 명시 |
| 멘토 말투 이탈 | System Prompt에 예시 대사 포함, 출력 길이 제한 |
| 부적절한 입력 | 입력 길이 제한, 금지 주제 필터 |
| 할루시네이션 | A2 퀘스트용 오류 답변은 **사전 제작한 정답 데이터셋** 사용 |

## 8. 시스템 구조

### 8.1 아키텍처

```mermaid
graph TD
    User([사용자]) --> UI[Streamlit 웹 UI]
    subgraph "Service Layer"
        UI --> Camp[⛺ Prompt Camp]
        UI --> Academy[🏛️ Prompt Academy]
        UI --> Lab[🔬 튜닝 연구소]
        UI --> Note[🎖️ 훈련 수첩]
        UI --> FB[💬 피드백]
    end
    subgraph "AI & Memory Layer"
        Camp --> Orch[Orchestrator]
        Academy --> Orch
        Lab --> Orch
        Orch --> Eval[Evaluator Agent]
        Orch --> Tune[Tuning Agent]
        Orch --> Persona[Persona Agent]
        Eval --> LLM[OpenAI gpt-4o-mini]
        Tune --> LLM
        Persona --> LLM
        Orch <--> Mem[(Firestore: Memory)]
        FB --> FDB[(Firestore: Feedback)]
    end
```

### 8.2 기술 스택

| 영역 | 선택 | 비고 |
| :--- | :--- | :--- |
| 언어/프레임워크 | Python 3.10+, Streamlit | 빠른 반응형 UI, 좌우 분할은 `st.columns` |
| LLM | OpenAI `gpt-4o-mini` | 비용 대비 성능, JSON 출력 지원 |
| 저장소 | Firestore (개발 단계는 로컬 JSON 폴백) | ⚠️ Streamlit Cloud는 로컬 파일이 초기화될 수 있어 **영속 DB 필요** |
| 배포 | Streamlit Community Cloud | API 키는 Secrets로 관리 |
| 협업 | GitHub | 브랜치 전략, README 관리 |

> 스택은 팀 역량에 맞게 변경 가능합니다. 다만 **메모리 영속성**은 반드시 확보하세요.

## 9. 일정 및 역할 분담

### 9.1 역할

| 팀원 | 역할 | 담당 업무 |

| 팀원 3 | AI / Memory | Memory 모듈, 멘토 System Prompt, 취약점 분석 로직 |
| 팀원 4 | Backend / Data | 퀘스트 데이터셋, 저장소 연동, 피드백 파이프라인 |
| 팀원 5 | QA / 배포 | 배포, 실사용자 테스트, 피드백 수렴, README |

### 9.2 4주 일정

| 주차 | 목표 | 세부 작업 | 산출물 |
| :-: | :--- | :--- | :--- |
| 1주 | 기획·설계 | 문제 정의, 기능 명세 확정, 와이어프레임, 퀘스트 목록·데이터 모델 확정 | 본 계획서, 와이어프레임 |
| 2주 | AI 엔진 구축 | 3종 에이전트 프롬프트 튜닝, Memory 설계·연동, 퀘스트 C1~C5 데이터 제작 | 에이전트 모듈, 퀘스트 데이터 |
| 3주 | 웹 구현 | Streamlit UI, 멘토 선택·Camp·연구소·훈련 수첩 구현, Academy A1~A3 | 동작하는 MVP |
| 4주 | 배포·검증 | 배포, 실사용자 5인 이상 테스트, 피드백 반영, README | 배포 URL, 테스트 결과 |

### 9.3 주차별 체크포인트

- **1주 말**: 화면 8종 와이어프레임 완료, 퀘스트 문항 초안 완료
- **2주 말**: 연구소 단일 플로우(입력→튜닝→코칭) 콘솔에서 동작
- **3주 말**: 외부 접속 없이 전체 흐름 시연 가능
- **4주 중**: 배포 URL 공개 후 테스트 시작

## 12. AI 윤리 및 개인정보

- 모든 AI 생성 결과에 **"AI가 생성한 콘텐츠입니다"** 문구 표기
- 수집 정보는 **닉네임과 학습 이력**으로 최소화, 실명·연락처는 받지 않음
- 첫 접속 시 데이터 수집·이용 안내 및 동의 절차 제공
- 사용자가 입력한 프롬프트는 학습 기록 목적으로만 사용하며, 삭제 요청 방법을 안내
- 멘토 캐릭터는 창작 캐릭터이며 실존 인물과 무관함을 명시
