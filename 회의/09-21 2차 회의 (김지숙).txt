## 1. 프로젝트 기본정보

**프로젝트명**: 새길 (가칭, New Path)

**한 줄 소개**: 대화형 AI가 중장년층의 경력·자격·희망 분야를 파악해 맞춤형 진로 경로와 실행 로드맵을 제시하고, 공공 지원사업 정보를 연결해 실행을 돕는 서비스

**팀 규모**: 5인 (안성현·김지숙·김지혜·이수지·이미지)

**타깃 사용자**: 은퇴를 앞두거나 경력단절을 겪은 40~60대 중장년층 중, 재취업·창업·재교육을 고려하는 사람

---

## 2. 문제 정의

### 핵심 Pain Point
중장년층은 진로 전환이 필요한 시점에 자신에게 맞는 선택지를 스스로 정리하기 어렵고, 관련 지원제도 정보가 여러 기관에 흩어져 있어 실행까지 이어지지 못한다.

### 문제 발생 상황
정년퇴직, 명예퇴직, 경력단절 이후 재취업이나 창업을 준비하는 시점에 구체적으로 무엇을, 어떤 순서로 준비해야 할지 판단할 근거가 부족한 상황.

### 문제의 근거
- 정부·지자체의 중장년 재취업·재교육 지원사업이 다수 존재하지만 고용24, 각 지자체 홈페이지 등으로 분산되어 있음 (공공데이터)
- 기존 진로 상담 서비스(원더풀시니어, 중장년내일센터 등)는 대면·오프라인 상담 중심으로 운영됨 (경쟁 서비스 조사)
- ※ 정량적 통계나 설문 데이터는 아직 확보되지 않았으며, 팀 내 실사용자 테스트를 통해 보완 예정

### 기존 솔루션
- 원더풀시니어(사람인): 진단 기반 중장년 재취업 컨설팅
- 중장년내일센터(고용24): 공공 전직·취업 지원 서비스
- 멘멘토 등 일반 진로 상담 앱: 전 연령 대상

### 기존 솔루션의 한계
- 사람 중심 상담이라 접근성과 확장성에 제약이 있음
- 오프라인/대면 중심이라 시간·장소 제약이 있음
- 전 연령 대상 서비스는 중장년의 특수한 상황(재교육 지원금, 경력 전환 특화 정보)을 반영하지 못함

### 우리 서비스의 차별점
AI 대화형 온보딩으로 접근성을 높이고, 로드맵 시각화와 공공 지원사업 실시간 연동을 결합해 "추천에서 끝나지 않고 실행까지 관리"하는 것이 차별점.

---

## 3. AI 기술 설계

### 사용할 AI 모델
Google Gemini API (무료 티어 활용)

### AI가 담당하는 기능
1. 대화형 온보딩 (사용자 정보 수집)
2. 진로 경로 추천 (경력·자격·희망분야 분석)
3. 로드맵 생성 (교육과정·기간·비용 구조화)
4. 주간 체크인 메시지 생성

### 왜 AI가 반드시 필요한가?
- 정형화된 설문으로는 사용자의 맥락(경력, 강점, 제약 조건)을 충분히 파악하기 어려움 → 대화형 접근이 필요
- 추천 로직이 규칙 기반이 아니라 개인 맥락에 따라 유연하게 조정되어야 함 → LLM의 추론 능력 필요
- ⚠️ 검증 필요: 단순 프롬프트 호출에 그치지 않으려면, 추천 결과를 구조화된 로드맵 포맷으로 변환하는 별도 로직(파싱/검증)이 반드시 있어야 함

### AI 처리 과정
```
사용자 입력 (경력, 자격, 희망분야, 가용시간)
   ↓
데이터 전처리 (대화 로그 → 구조화 데이터 추출)
   ↓
AI 처리 (Gemini API — 진로 경로 추천 + 로드맵 생성)
   ↓
결과 검증 (추천 경로가 실제 존재하는 직업/과정인지 확인, 형식 검증)
   ↓
서비스 로직 (공공 API 데이터와 매칭, 로드맵 구조화)
   ↓
사용자 출력 (타임라인 형태 로드맵 + 추천 이유)
```

### AI 오류/환각 대응
- 존재하지 않는 자격증·과정명을 생성하지 않도록, 추천 시 공공 데이터(고용24, 워크넷)와 대조 검증
- 검증 실패 시 "일반적인 방향성 제안"으로 폴백하고, 사용자에게 확인 필요 문구 표시

### AI 비용 관리
- Gemini 무료 티어 사용, 일일 요청 한도 관리 필요 (환율 챗봇 프로젝트에서 겪었던 이슈와 동일한 리스크 존재 → 캐싱/요청 최소화 설계 필요)

## 4. 사용자 경험 설계

### 핵심 User Flow
로그인/시작 → 대화형 온보딩 → 진로 경로 추천 확인 → 경로 선택 → 로드맵 생성 → 로드맵 확인/저장 → 주간 체크인 알림 수신 → 진행 상황 업데이트

### 사용자의 최초 진입
서비스 소개 화면에서 "내 진로 찾기 시작하기" 버튼으로 온보딩 챗봇 진입

### 핵심 행동
온보딩 대화 완료 → 추천 경로 3~5개 중 선택 → 로드맵 확인

### AI 결과 확인
타임라인 형태의 로드맵 화면에서 단계별 교육과정, 예상 기간, 비용을 확인

### 사용자가 결과를 활용하는 방법
로드맵을 기준으로 실제 교육 신청, 지원사업 신청 등 행동으로 이어짐

### 재방문 이유
주간 체크인 알림, 새로운 지원사업/공고 알림으로 재방문 유도

## 5. 서비스 플랫폼 설계 (페이지 구조)

### 온보딩 페이지
- 목적: 사용자 정보 수집
- 사용자: 신규 방문자
- 입력: 대화형 텍스트
- 처리: Gemini API 호출, 구조화 데이터 추출
- 출력: 진로 경로 추천 리스트
- 사용 API: Gemini API
- 사용 AI: 대화형 추천 로직
- 사용 DB: Firestore (사용자 프로필)
- 예외처리: 응답 지연 시 로딩 상태 표시, API 오류 시 재시도 안내
- 다음 페이지: 경로 추천 결과 페이지

### 경로 추천 결과 페이지
- 목적: 추천된 진로 경로 비교·선택
- 입력: 사용자의 경로 선택
- 처리: 선택된 경로에 대한 로드맵 생성 요청
- 출력: 로드맵 페이지로 이동
- 사용 DB: Firestore (추천 결과 저장)
- 다음 페이지: 로드맵 페이지

### 로드맵 페이지
- 목적: 실행 계획 시각화
- 처리: 로드맵 데이터 구조화, 공공 API 연동 정보 매칭
- 출력: 타임라인 UI
- 사용 API: 고용24/워크넷 공공 API
- 사용 DB: Firestore (로드맵 저장)
- 예외처리: 공공 API 응답 없을 시 AI 생성 정보만으로 표시 + 안내 문구
- 다음 페이지: 대시보드/마이페이지

### 마이페이지 (체크인)
- 목적: 진행 상황 관리
- 처리: 주간 체크인 메시지 생성 및 진행률 업데이트
- 사용 DB: Firestore (진행 이력)
- 다음 페이지: 없음 (순환 구조)

  ↓

  ↓

## 8. 기술 완성도 자체 점검 체크리스트

**모델/알고리즘**
- [ ] AI 모델을 단순 API 호출만 하지 않고, 결과 검증/구조화 로직을 별도로 구현했는가
- [ ] AI 결과를 그대로 노출하지 않고 서비스 로직(공공데이터 매칭 등)을 거치는가

**코드**
- [ ] 온보딩/추천/로드맵 기능이 모듈화되어 있는가
- [ ] API Key 등 민감정보를 환경변수로 관리하는가
- [ ] 예외처리(API 실패, 빈 응답 등)가 되어 있는가

**성능/비용**
- [ ] Gemini API 일일 요청 한도 내에서 동작하도록 캐싱/요청 최소화를 설계했는가

## 9. Final Project 평가기준 자체 검증 (기획 단계 기준)

> ⚠️ 아직 구현 전 단계이므로, 아래는 "현재 기획의 완성도"에 대한 자체 점검이며 실제 구현 후 재검증이 필요합니다. 확인되지 않은 수치나 성과는 기재하지 않았습니다.

### 심사위원 관점 한 줄 총평 (기획 단계 기준)
문제 정의와 차별점은 명확하나, AI가 "단순 추천 API 호출"에 머물지 않으려면 결과 검증·공공데이터 결합 로직의 실제 구현이 관건이다.

### 자체 점검표 (구현 전 — 정성 평가만 가능)

| 평가영역 | 배점 | 현재 상태 | 비고 |
|---|--:|---|---|
| 기획·창의성 | 30 | 문제정의·차별점 명확, 경쟁 서비스 조사 완료 | 정량적 문제 근거(설문/통계) 보완 필요 |
| 기술 완성도 | 20 | 미평가 | 구현 후 검증 필요 |
| 실용 가능성 | 10 | 설계상 타당 | 실사용자 테스트로 검증 필요 |
| 팀 구성·협업 | 30 | 역할 분담 완료 | Git/Issue/PR 등 협업 증빙은 진행 중 축적 필요 |
| 발표·전달력 | 10 | 미평가 | 발표 자료 제작 후 검증 필요 |

### 가장 큰 강점 (3개 이내)
1. 중장년 특화 + AI 대화형 + 공공데이터 연동을 결합한 명확한 차별점
2. 문제-해결-AI 기능이 논리적으로 연결됨
3. 실사용자 테스트가 1인 사용자 구조라 비교적 용이함 (매칭 불필요)

### 가장 위험한 감점 요소 (5개 이내)

**1. 문제**: 정량적 문제 근거 부족
- **왜 감점될 수 있는가**: 평가기준 "문제를 뒷받침하는 근거"가 현재 정성적 추론 수준
- **수정방법**: 간단한 설문(5~10명) 또는 공공 통계 인용 추가
- **필요한 산출물**: 설문 결과 또는 통계 출처

**2. 문제**: AI가 단순 API 호출에 그칠 위험
- **왜 감점될 수 있는가**: "AI 기술 적용 및 논리적 기획" 20점 항목에서 감점 가능
- **수정방법**: 결과 검증 로직, 공공데이터 결합 로직을 명확히 구현하고 문서화
- **필요한 산출물**: 결과 검증 코드/로직 다이어그램

**3. 문제**: 공공 API 연동 실패 시 대응 미흡
- **왜 감점될 수 있는가**: 예외처리·구조적 완성도 감점 가능
- **수정방법**: API 실패 시 폴백 로직 설계 및 테스트
- **필요한 산출물**: 예외처리 테스트 케이스

**4. 문제**: 팀 기여도 편중 가능성
- **왜 감점될 수 있는가**: 역할·기여도 20점 항목에서 특정 팀원 편중 시 감점
- **수정방법**: Git Commit/Issue를 팀원별로 고르게 분배해 기록
- **필요한 산출물**: 역할분담표 + Git 기록

**5. 문제**: BM(수익모델) 미정
- **왜 감점될 수 있는가**: 실용 가능성 항목 중 "유료 확장 가능성" 부분 감점 가능
- **수정방법**: 최소한의 BM 가설(예: 공공기관 B2G 제휴, 프리미엄 로드맵 등) 정리
- **필요한 산출물**: BM 슬라이드 1장

### AI 기술 검증
- **단순 호출 여부**: 현재 설계상으로는 검증/구조화 로직이 포함되어 있어 "아니오"에 가깝지만, 실제 구현에서 반드시 지켜야 함
- **AI의 핵심 역할**: 사용자 맥락을 이해해 개인화된 진로 경로와 로드맵을 생성
- **AI가 없을 경우 사라지는 핵심 기능**: 개인 맥락 기반 추천 자체가 불가능해지고 정적 정보 나열 서비스로 전락
- **AI 기술을 강화할 방법**: 사용자 이력 기반 Long-term Memory 도입, 추천 경로에 대한 근거를 RAG로 보강
